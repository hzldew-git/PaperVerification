\begin{abstract}
This document records the reproducible Mathematica checks associated with
\texttt{Trace-Euclidean-v8.tex}.  It records the SHA-256 digest of the private
manuscript version used to prepare the extracted inputs, maps each mathematical
component to a named code module and stable internal LaTeX anchor, and imports
all numerical results from machine-readable output.  In the pages below, those anchors are rendered as the theorem,
equation, section, and table numbers in the compiled manuscript, together with
page numbers where they help direct comparison.
Exact identities, certified interval calculations, finite enumerations, and
finite diagnostics are kept distinct.  The accompanying workflow is designed
so that a later manuscript revision requires changes only in the affected
manifest entry or check module; the result tables in this document are then
regenerated automatically.
The public repository intentionally excludes both the manuscript TeX source and
the rendered manuscript PDF.
\end{abstract}

\section{Purpose and evidence boundary}

The package checks the formulas and finite computations used in the manuscript.
A record marked \texttt{PASS} establishes only the scope stated for that check.
In particular, a finite diagnostic does not prove a theorem for all number
fields or all lattice vectors, and a high-precision root approximation does not
certify existence or uniqueness.  General compactness, monotonicity, finiteness,
and source-dependent assertions remain mathematical arguments in the manuscript.

The evidence classes used here are:
\begin{enumerate}[label=\textup{(\roman*)}]
\item an \emph{exact symbolic identity}, simplified with exact input;
\item a \emph{certified rational interval}, whose endpoints are exact rational
numbers and whose sign excludes zero;
\item a \emph{finite enumeration}, over the complete rectangle recorded below;
\item a \emph{high-precision approximation}, used only to check printed decimals;
\item a \emph{finite diagnostic}, explicitly limited to the configured sample.
\end{enumerate}

\paragraph{Publication boundary.}
The repository-level publication check permits only explicitly listed
verification-document \texttt{.tex} and \texttt{.pdf} files.  It rejects
the private source-snapshot and manuscript-build directories, complete TeX or
PDF documents outside that allowlist, and opaque archives.  Consequently, the
recorded source digest identifies the manuscript version used for extraction
without distributing the manuscript source or its rendered PDF.

\section{Version binding and recorded run}

The private maintainer extraction step computes the SHA-256 digest of the
manuscript snapshot.  During that build, the Mathematica driver recomputes the
digest before loading any mathematical module, so a changed snapshot cannot
silently reuse stale inputs.  The public repository does not contain that
snapshot.  A public run therefore reads the recorded digest from
\nolinkurl{inputs/manuscript_inputs.json}, checks its form and agreement with
the result metadata, and then reruns the published calculations.  This permits
independent reproduction of the computations without distributing the
manuscript itself.

\input{run_summary.tex}

The status convention is as follows.  A \texttt{FAIL} is a failed exact,
certified, coverage, or integrity check and gives batch exit code~1.  A
\texttt{WARN} records a manuscript presentation or rounding issue while the
verification engine remains internally consistent and gives exit code~2.  A
run with neither gives exit code~0.

\section{Analytic definitions and extrema}

The code uses the manuscript definitions
\begin{align*}
a&=\frac{1}{6},
&b&=\frac{e^{2}}{2\pi}-1,\\
K(x)&=\log(2\pi)-\log x-1,
&g(x,y)&=x\log(2\pi(y+b))-\log(\pi(xy+2a))+xyK(x),\\
g_{\mathfrak{s}}(x,y)&=\frac{g(x,y)}{x},
&g_{\mathfrak{n}}(x,y)&=y\log 2+\frac{g(x,y)}{x}.
\end{align*}
The module first compares exact symbolic derivatives with the displayed
formulas.  It then checks the signs needed at the stated thresholds by rational
interval arithmetic.  The roots returned by \texttt{FindRoot} at 80-digit
working precision are used only for the following comparison with decimals
printed in the manuscript.

\section{Certified interval construction}

The interval implementation uses exact rational endpoints.  It bounds
\(\pi\) through Machin's identity
\begin{align*}
\pi=16\arctan\left(\frac{1}{5}\right)
-4\arctan\left(\frac{1}{239}\right)
\end{align*}
and an alternating arctangent series through exponent~121.  It bounds \(e\)
by the sum through \(1/100!\) together with an explicit geometric remainder.
For a positive rational number, powers of~2 first reduce the logarithm argument
to \([1,2]\); with \(u=(r-1)/(r+1)\), the code uses
\begin{align*}
\log r
=2\sum_{j=0}^{47}\frac{u^{2j+1}}{2j+1}+R,
\qquad
0\le R\le\frac{2u^{97}}{97(1-u^{2})}.
\end{align*}
Every arithmetic operation is rounded outward to 40 decimal places, while the
stored endpoints remain rational numbers.  Consequently, a certified positive
or negative sign does not depend on floating-point evaluation.

\section{Admissible-pair tables}

For the classical case the complete rectangle is
\(3\le n\le12\), \(1\le d\le10\); for the integral case it is
\(5\le n\le29\), \(1\le d\le57\).  The computation classifies every
integer point by a rational interval for
\(g_{\mathfrak{s}}(n,d)\) or \(g_{\mathfrak{n}}(n,d)\), and compares the
positive set with the rows extracted from the two admissible-pair tables.
The tail signs at \((13,1)\), \((3,11)\), \((30,1)\), and \((5,58)\)
are certified separately.  Exhaustion outside the two rectangles also uses the
monotonicity lemmas in the manuscript.

\section{Trace Gram and Voronoi calculations}

The trace-Gram module tests non-diagonal binary Gram matrices together with
distinct fractional principal ideals over several real quadratic fields.  All
entries and determinants are reduced exactly modulo \(z^{2}-m\).  These tests
check the determinant formula on deliberately nontrivial inputs; the general
formula remains the symbolic proof in \msref{lem:gram-det}.

For the hexagonal case, the code solves the adjacent bisector equations exactly
and verifies all six displayed facet inequalities.  If
\begin{align*}
G=\begin{pmatrix}p&r\\r&q\end{pmatrix},
\end{align*}
then the computed vertex norm is simplified to
\begin{align*}
\frac{pq(p+q-2r)}{4(pq-r^{2})}.
\end{align*}
After substituting the real-quadratic Gram matrix, each vertex has squared norm
\((m+1)^{2}/(8m)\).  The additional enumeration over square-free
\(2\le m\le200\) is a finite diagnostic; completeness of the Voronoi facets
for arbitrary \(m\) comes from the manuscript's geometric argument.

\section{Reproduction}

The public code, extracted inputs, results, and documentation are available at
\url{https://github.com/hzldew-git/PaperVerification/tree/main/Trace-Euclidean-v8}.
To rerun the published calculations from the package root, use:
\begin{Verbatim}[fontsize=\small,breaklines=true]
wolframscript -file run_verification.wls
python tools/build_report.py
python tools/check_delivery.py
\end{Verbatim}
No manuscript file is required for these commands.  To inspect variables
interactively, evaluate
\begin{Verbatim}[fontsize=\small,breaklines=true]
Get[".../verify_trace_euclidean_v8.m"]
\end{Verbatim}
in Mathematica.  The \texttt{.m} file deliberately does not call
\texttt{Exit}; only \texttt{run\_verification.wls} turns the recorded
status into a batch exit code.

After a manuscript revision, the maintainer keeps the manuscript outside the
Git repository and runs the private refresh pipeline with:
\begin{Verbatim}[fontsize=\small,breaklines=true]
.\build_all.ps1 -ManuscriptPath 'D:\private\path\Trace-Euclidean-v8.tex'
\end{Verbatim}
The temporary source snapshot and compiled manuscript are written only to
ignored private-work directories.  The pipeline regenerates the extracted
inputs, displayed manuscript numbering, result files, and this verification
manual, then invokes the repository manuscript-exclusion check.  The optional
executable parameters may be used when Python, WolframScript, or TeX Live is
installed elsewhere.  No network connection or third-party Wolfram package is
required for the calculation run.
